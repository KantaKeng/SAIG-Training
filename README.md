# Traffic Forecast for Lat Krabang
โปรเจกต์นี้เป็น Prototype ที่ทำส่งแลป SAIG เป็นระบบทำนายสภาพการจราจรในพื้นที่ลาดกระบังล่วงหน้าประมาณ 15–30 นาที โดยใช้ Machine Learning ร่วมกับข้อมูลจาก Longdo Traffic API
ที่เลือกทำหัวข้อนี้ เพราะช่วงที่เก็บข้อมูลและทดลองใช้งาน API สังเกตว่าพื้นที่ลาดกระบังมีรถติดค่อนข้างบ่อย โดยเฉพาะบริเวณที่มีทางตัดรถไฟ เวลาไม้กั้นปิด รถจะสะสมจากหลายฝั่ง พอไม้กั้นเปิด รถก็จะออกพร้อมกัน ทำให้เกิดรถติดอยู่พักหนึ่ง เลยอยากลองสร้างระบบที่ช่วยบอกล่วงหน้าว่าอีกประมาณ 15–30 นาที ถนนเส้นนั้นจะมีแนวโน้มเป็นยังไง
โปรเจกต์นี้ไม่ได้ทำมาเพื่อแทนแอปนำทางอย่าง Google Maps เพราะไม่ได้คำนวณเส้นทางหรือหาเส้นทางที่เร็วที่สุด แต่เน้นใช้ Machine Learning วิเคราะห์ข้อมูลการจราจรที่ผ่านมา แล้วทำนายแนวโน้มของสภาพการจราจรในอนาคต เพื่อใช้เป็นข้อมูลช่วยตัดสินใจก่อนออกเดินทาง

# System Flow
เวลาผู้ใช้กดปุ่ม **Analyze** ระบบจะทำงานตามขั้นตอนดังนี้

1. รับตำแหน่ง GPS ของผู้ใช้ผ่าน Browser (`navigator.geolocation`)
2. ส่งพิกัดไปยัง Backend ที่พัฒนาด้วย Flask
3. Backend เรียก Longdo Traffic API เพื่อดึงข้อมูลของตำแหน่งนั้น เช่น
   - ความเร็วการจราจรปัจจุบัน
   - ชื่อถนน
   - พิกัดหลัง Coordinate Snapping
4. นำข้อมูลที่ได้มาสร้าง Feature สำหรับ Machine Learning
   - แยก Hour และ Minute
   - แปลงเวลาเป็น Hour_Sin และ Hour_Cos
   - คำนวณ Snapping Distance ด้วยสูตร Haversine
   - สร้าง Historical Speed, Lag Feature และ Rolling Mean
5. ส่ง Feature เข้าโมเดล XGBoost เพื่อทำนายความเร็วเฉลี่ยในอีก 15–30 นาที
6. นำค่าความเร็วที่ทำนายได้มาแปลงเป็นระดับการจราจร
   - Low
   - Medium
   - High
7. แสดงผลพร้อมคำแนะนำบนหน้าเว็บ
ตัวอย่างผลลัพธ์

> อีก 15 นาที ถนนเส้นนี้มีแนวโน้มรถติดมาก คาดว่าความเร็วเฉลี่ยจะลดลงเหลือประมาณ 13 km/h แนะนำให้หลีกเลี่ยงเส้นทางนี้หากไม่จำเป็น

#After Coding
ตอนทำโปรเจกต์นี้มีหลายอย่างที่ไม่ได้เป็นไปตามที่คิดไว้ บางเรื่องใช้เวลาแก้นานกว่าที่คิด และหลายอย่างก็ต้องเรียนรู้ระหว่างทำ
ตอนแรกคิดว่าเปิด Documentation แล้วทำตามได้เลย แต่พอลองใช้งานจริง หลาย Endpoint ต้องลองยิง Request เอง แล้วเปิดดู Response ว่าแต่ละฟิลด์คืออะไร บางอย่างไม่มีตัวอย่างให้ ต้องค่อย ๆ ลองไปทีละแบบ
อีกเรื่องที่เจอคือสิทธิ์ของ API ตอนแรกใช้ Key ที่มีอยู่ แล้วเพิ่งมารู้ทีหลังว่าบางบริการเรียกได้ แต่บางบริการเรียกไม่ได้ อย่าง Reverse Geocoding ใช้ได้ปกติ แต่ Traffic Speed กับ Route ต้องขอสิทธิ์เพิ่ม ทำให้ต้องกลับมาแก้ Backend ใหม่
Longdo ส่งค่าความเร็วเป็น m/s แต่ข้อมูลที่ใช้เทรนโมเดลเป็น km/h
ช่วงแรกผมลืมแปลงหน่วย ทำให้ผลที่ทำนายออกมาเพี้ยนไปหมด กว่าจะรู้ว่าผิดตรงนี้ก็ใช้เวลาหาอยู่พักหนึ่ง
ตอนแรกเผลอเอา Risk Level ไปเป็น Target ของโมเดล ทั้งที่จริงควรใช้ค่าความเร็ว ผลที่ได้เลยไม่ตรงกับที่ต้องการ
สุดท้ายเลยแยกให้ชัดว่า โมเดลมีหน้าที่ทำนายความเร็ว ส่วนการแบ่งเป็น Low, Medium และ High ค่อยทำหลังจากโมเดลทำนายเสร็จ

### ทดสอบโมเดล
ตอนวัดผลบน Test Set ผลออกมาค่อนข้างดี แต่พอลองเอาไปใช้กับข้อมูลจริงกลับได้ผลไม่เหมือนกัน
สุดท้ายเลยเปลี่ยนวิธีทดสอบ โดยให้โมเดลทำนายล่วงหน้า แล้วรอข้อมูลจริงประมาณ 15 นาที เพื่อนำมาเปรียบเทียบกับค่าที่ทำนายไว้

### Deploy
ช่วงแรกเซฟโมเดลด้วย Joblib จาก Google Colab แต่พอเอามารันบน Windows กลับโหลดไม่ขึ้น เพราะเวอร์ชันของ XGBoost ไม่ตรงกัน
สุดท้ายเลยเปลี่ยนมาใช้ไฟล์ `.json` ของ XGBoost แทน ซึ่งใช้งานข้ามเครื่องได้ไม่มีปัญหา
